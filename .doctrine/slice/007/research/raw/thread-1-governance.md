### Revision candidates

- **DEC-026, bounds clause** — "items that each get an equal share of the rest… each whole or left out (only the core's subject and message_id are ever shortened)". If answers are shown on `mail_new` they consume the share; leaving whole answers out under body pressure hides the very thing the slice delivers. Amend to fix answers' place in the fill order (before body, or a summarised core fragment: choice + confidence) and to say answers are bounded (probabilities dropped first).
- **DEC-026 + DEC-028 (5) partial-run clause** — "each line must be a complete v1 envelope or the call fails" / "any failure fails the call… no partial data". `screwtape-readme.md` "Resume and skip": classify "stops at the first failure, keeping the lines before it" and prints an error line with that message's cursor. Either the mail tools accept a bounded partial classification set (contradicting the clause) or they must re-run per message. Needs an explicit per-verb exception.
- **DEC-026, port clause** — "a classifier stage can replace `readAfter` later" is too strong: classify returns `classify` envelopes, so `readAfter`'s contract changes. Add a `classify`/`readClassified` port member and its validated schema.
- **DEC-027** — a cache is state. Add the clause IMP-022 offers: cache lives below the tools, keyed (id, `model`, `schema`), is not caller state, and replay safety means identical output for identical content, not no state.
- **DEC-028 (2)** — "10 s timeout", "minimal child env (HOME)". A transient unit + Jev call per batch may exceed 10 s; and HOME alone cannot reach `$CREDENTIALS_DIRECTORY`. Revise to name the classify invocation (wrapper path, its own timeout) and drop HOME-alone for `classify`.
- **ASM-001** — supersede or rescope: the assumption holds for read verbs, not for `classify` (obj. 3).
- **RSK-002 controls facet** — "pre-read classifier planned, not built" becomes built, with the caveat that answers are advice.
- **DEC-029/DEC-030** — only if a new tool is chosen (catalog + guard test) or answer rendering needs a new pinned rule.

### Contract facts design will need

- **classify in/out** ("classify"): no arguments; reads version-1 `read` envelopes, one per line on stdin; writes one `classify` envelope per input line, in input order, kind `classify`, version 1. Fields: `id`, `cursor`, `schema` (always `mail-1`), `model` ("the model the reply reports, as accepted: the configured model, or its text after the last `/`"), `answers`.
- **Answer shapes**: `choice` → label + `probabilities {label: float}` (sum 1±0.02) + `confidence`; `noul` → probability 0–1; `score` → level 0…n-1, within 0.05 of Σ i·p_i, `probabilities` keyed `"0"`…`"n-1"`, plus `confidence`. `mail-1` order is print order: `primary_purpose` (7 labels), `security_related`, `recipient_action_requested`, `deadline_present`, `deception_cues`, `agent_directive`, `claimed_time_pressure` (3 levels), `substance` (3 levels).
- **Failure lines / exit codes** ("CLI"): stderr one JSON object per line, `reason` a fixed code; `no_jev` → `{"error":"config"}`, exit 2; `no_stdin` → `{"error":"usage"}`, exit 2; ceilings/transport/credential → exit 1. Per-message failure: `{"level":"error","error":"limit_exceeded","bound":"jev_context","cursor":"…"}`, exit 1.
- **Partial run** ("Resume and skip"): stops at the first failure, keeps earlier lines on stdout; resume with `read --after <that cursor>`, which "starts past the message, so the run skips it" — and "The same move skips any message that fails on every run" (so a permanently failing message is silently dropped unless marked unclassified).
- **stdin cap** ("Bounds"): classify reads at most 16 MiB of stdin, else `limit_exceeded`/`stdin_bytes`, exit 1; "Page the selection with `read --limit`". `--max-bytes` caps body text per message, so a page can be ≤ limit × max-bytes — that product, not the rendered size, is the batch budget.
- **Key ingress** ("The key, and the wrapper"): with `jev` set the Home-Manager wrapper runs `classify` (not `--state`) as `systemd-run --user --pipe --quiet --wait --collect -p LoadCredentialEncrypted=jev:<configHome>/credstore.encrypted/screwtape.jev -p LimitCORE=0 -E ERL_CRASH_DUMP_SECONDS=0 screwtape --config <file> classify`; otherwise the key comes only from `$CREDENTIALS_DIRECTORY`. `classify --state` needs neither the `jev` block nor the credential — the only jail-side probe.
- **Jail reality** (measured, not assumed): `satan-flake.nix` binds `${package}/bin/screwtape` — the **unwrapped** binary — plus the config and store, into a `profile = "offline"` jail with gateway access only over `MALEBOLGE_GATEWAY_SOCKET`. So objective 3 cannot use the wrapper as currently configured, and Jev's `base_url` (`http://127.0.0.1:<relayPort>`) is not obviously reachable from that jail.
- **`--state`** ("classify_state"): prints what Jev would receive (`subject`, `sender_domains` + omitted count, `bodies` with `is_truncated`/`conversion_failed`, `attachments`), never asks Jev — a fixture/debug path for tests, not for answers.
- **Cost/latency** (OQ-4, "Bounds"): one transient unit + one Jev call per message; batch one `read --after` page into a single `classify` invocation, and do not invoke `classify` at all for a page where every message is cached.
