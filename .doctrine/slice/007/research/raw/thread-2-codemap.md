### Cited facts

1. The port is five verbs, all returning contract-checked data: `mailboxes`, `list`, `read`, `readAfter`, `thread` (`src/mail/source.ts:245`–`251`).
2. Failures are the closed set `"usage" | "failed" | "timeout" | "spawn" | "contract" | "oversize"` (`src/mail/source.ts:254`), carried by `MailSourceError` whose message is "safe to show the model (never raw stderr)" (`src/mail/source.ts:256`–`257`).
3. Contract checking is one table: `KIND_SCHEMAS` maps `mailboxes|list|read|thread` to TypeBox schemas and `checkData` fails closed (`src/mail/source.ts:184`–`203`); extra fields are tolerated (`src/mail/source.ts:1`–`3`).
4. argv is built per verb as pure functions, filters in contract order (`src/mail/screwtape.ts:53`–`88`); the child is always `[binary, "--config", config, ...args]` (`src/mail/screwtape.ts:245`–`246`).
5. Env is exactly `{ HOME }` with `inheritEnv: false`, `timeout: MAIL_TIMEOUT_S` = 10 s (`src/mail/screwtape.ts:252`, `:34`).
6. stdout is capped at 4 MiB per line and in total, stderr at 4 KiB, `oversize: "fail"`, and a breach aborts the child (`src/mail/screwtape.ts:236`–`244`, `:258`–`262`).
7. Arity is checked after exit: exactly one envelope, or at most `limit` (`src/mail/screwtape.ts:174`–`176`, `:268`–`270`); `runMany` passes `limit` as `max` (`src/mail/screwtape.ts:291`–`296`).
8. Fail-closed contract checks run in a fixed order — not JSON, version, kind, data — each naming a fixed `Violation` word (`src/mail/screwtape.ts:100`–`108`, `:184`–`203`); a leftover partial line fails as `unterminated line` (`src/mail/screwtape.ts:266`–`268`).
9. stderr is read only for a usage code: exit 2 → first error-level JSON line's `reason`, kept only if it matches `/^[a-z_]{1,64}$/` (`src/mail/screwtape.ts:48`, `:140`–`147`, `:160`–`168`); anything else is `screwtape failed (exit N)`.
10. Timeout and spawn are rewritten in the adapter's words; other `ExecutionError`s pass through untouched (`src/mail/screwtape.ts:125`–`134`).
11. **stdin cannot be supplied today.** `ShellExecOptions` has `cwd`, `env`, `inheritEnv`, `timeout`, `onOutput`, `spill`, `window` — no stdin/input field (`node_modules/@earendil-works/pi-durable/dist/env/index.d.ts:237`–`253`), and `exec` accepts only `string | readonly string[]` (`:298`).
12. `NodeExecutionEnv.exec` spawns argv commands with `stdio: ["ignore", "pipe", "pipe"]` and only pipes stdin for a legacy WSL shell's `-s` command transport (`node_modules/@earendil-works/pi-durable/dist/env/node.js:742`–`753`).
13. The only in-repo workaround would be passing a *string* command, which runs through the shell (`dist/env/node.js:598`–`608`) — that breaks DEC-028's "no shell" property and the argc-safe argv discipline (`src/mail/screwtape.ts:1`–`3`), and `boundedExec` types its command as `readonly string[]` (`src/bounded-exec.ts:150`–`152`). Real support needs a stdin field (or a `writeFile`+`<` convention) added to pi-durable's `ShellExecOptions` and `exec`, plus passing it through `BoundedExecOptions.exec` (`src/bounded-exec.ts:139`–`143`).
14. `mail_new` clamps `limit` 1–20 and `max_bytes` 512–8192 with the joint `max_bytes ≤ 40960/limit` (`src/mail/tools.ts:36`–`43`, `:83`–`90`), calls `source.readAfter` once (`src/mail/tools.ts:315`–`340`), computes `pagePosition` from validated envelopes (`src/mail/tools.ts:174`–`199`), and renders `page.map(projectNew)` with `limit` (`src/mail/tools.ts:336`–`345`).
15. `mail_read` clamps `max_bytes` 1024–32768 (`src/mail/tools.ts:38`), calls `source.read` once (`src/mail/tools.ts:346`–`351`), and renders `[projectRead(read)]` with `limit` 1 (`src/mail/tools.ts:352`).
16. Budget: whole result 50 KiB (pi's `DEFAULT_MAX_BYTES`), 2 KiB header reserve, 64 B wrapper charge, items get 48 KiB (`src/mail/render.ts:11`–`19`); per item `shareOf(limit) = (48 KiB − (limit−1)) / limit` (`src/mail/render.ts:28`–`30`).
17. Render order per item is **core whole, then fill entries each all-or-named-in-`cut`, then body cut to what remains** (`src/mail/render.ts:189`–`201`, `addFill` `:144`, `addBody` `:166`); exceeding the share throws rather than trims (`src/mail/render.ts:196`–`199`).
18. Everything rendered goes through `dataLine` (JSON + `<`,`>`,`&` escapes) and is measured on rendered bytes only (EX-2) (`src/mail/render.ts:2`–`6`, `:33`–`43`); the header is asserted within `HEADER_MAX_BYTES` and the result within `MAIL_MAX_BYTES` (`src/mail/render.ts:320`, `:330`).
19. Wiring: `screwtapeOf` yields `{binary, config, home}` only for profiles allowing `mail`, from `MALEBOLGE_SCREWTAPE` / `MALEBOLGE_SCREWTAPE_CONFIG`, absolute-path-checked, no existence check (`src/config.ts:96`–`110`, `:78`–`86`); `Config.screwtape` is optional (`src/config.ts:70`).
20. `mailPart` builds `screwtapeSource({...screwtape, env: new NodeExecutionEnv({ cwd: screwtape.home })})` plus `now` (`src/daemon-start.ts:139`–`156`), and the registry is constructed once per daemon start (`src/daemon-start.ts:221`), so anything held in the `MailDeps` closure is daemon-lifetime and shared by every conversation on that daemon.
21. Today **nothing is held across tool calls**: `MailDeps` is `{ source, now }` (`src/mail/tools.ts:208`–`211`), `src/mail/` contains no `Map`/cache at all, and the only keyed stores in `src/` are unrelated (`src/skills.ts:99`, `src/satan-pool.ts:51`, `src/runner/config.ts:391`).
22. A `memo` facility exists on the tool API but is **per-task**, not per-conversation: `memo<T extends JsonValue>(name, …)` (`node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:193`–`194`), documented as "the asking task's memos, which hooks and the task share" (`:772`–`779`), wired straight to `runtime.memo` (`dist/harness/tool.js:266`).

### Naming precedents

- Schemas: exported PascalCase consts + `type X = Static<...>` pairs (`AddressSchema`/`Address`, `ReadSchema`/`ReadData`, `MailboxesSchema`/`MailboxesData`), registered in `KIND_SCHEMAS` by verb name (`src/mail/source.ts:68`–`189`).
- Query types: `ListQuery`, `ReadQuery`, `ReadAfterQuery`, `ThreadQuery`, each with `signal?: AbortSignal | undefined` (`src/mail/source.ts:213`–`238`); new one should be `ClassifyQuery`.
- argv: one pure `xxxArgs(query)` per verb, contract order, `--flag value` pairs (`listArgs`, `readArgs`, `readAfterArgs`, `threadArgs`, `src/mail/screwtape.ts:65`–`96`).
- Constants: SCREAMING_SNAKE with a doc comment stating the *why* (`MAIL_STDOUT_MAX`, `OVERSIZE_AT_LIMIT_1`, `NEW_JOINT_BYTES`, `SUBJECT_MAX_BYTES`).
- Errors: lowercase fixed-vocabulary message prefixes — `"screwtape ..."` for adapter failures (`src/mail/screwtape.ts:118`–`131`), `"<tool>: <param> must be ..."` for input refusals (`src/mail/tools.ts:135`–`180`), `contract violation: <fixed word>` for output breaches.
- Cut names: enumerate in `CUT_ORDER`, and only via `orderedCuts` (`src/mail/project.ts:21`–`41`, `:112`–`115`).
- Header lines: fixed literal + validated value, one helper per line (`itemsLine`, `clampsLine`, `shownLine`, `src/mail/render.ts:263`–`290`).

### Gaps / surprises

- **No stdin, at all.** The adapter's whole contract is "argv in, stdout out" (fact 11–13). Everything about classify must either wait on a pi-durable `stdin` (or file-redirect) option, or go through a shell string — which contradicts DEC-028 and would need, at minimum, a widened `boundedExec` signature.
- **Raw envelope text is thrown away.** `run` keeps only checked `data` (`src/mail/screwtape.ts:233`–`277`); classify needs the original `read` JSON line, so the read path must retain lines (or re-`JSON.stringify` the data, which may drop contract-order/extra fields that classify cares about).
- **Read bodies are already truncated.** `max_bytes` bounds what `read` prints, so a classify answer can differ per `max_bytes`; a cache key of (id, model, schema) silently mixes truncated and untruncated bodies. Either key on more, or classify from a fixed full read.
- **Arity semantics do not fit.** `Arity` is `"one" | {max}` and `runMany` derives `max` from `limit` (`src/mail/screwtape.ts:50`, `:291`); classify's bound is "one line per piped message", and nothing today checks that returned ids match the requested ids/order — a new fail-closed check is needed.
- **Oversize advice is verb-specific.** `oversizeError` says "retry with limit 1" (`src/mail/screwtape.ts:113`–`121`) and `OVERSIZE_AT_LIMIT_1` is `mail_new`'s (`src/mail/tools.ts:47`–`52`); both are wrong advice for a batched classify, and a single 10 s timeout (`MAIL_TIMEOUT_S`) may be too short for a model call.
- **Budget collision with DEC-026.** Answers must render inside an item's `shareOf(limit)` (fact 16–17) unless they go somewhere else; the header reserve is only 2 KiB and is asserted (`src/mail/render.ts:320`), and any new answer text is untrusted model output, so it needs `dataLine` escaping plus a sentence in `MAIL_SECTION` (`src/mail/extension.ts:9`).
- **Test friction.** `fakeMailSource` rejects verbs it has no reply for (`test/mail/mail-fixtures.ts:573`–`575`) and `tools.test.ts` asserts exactly one recorded call per tool; adding a classify call breaks roughly every `onlyQuery` assertion unless the fake grows a classify reply and the assertions become verb-filtered.
- **Cache scope is a design decision with no precedent here.** A closure `Map` in `MailDeps` is daemon-lifetime and cross-conversation (fact 20); `api.memo` is per-task and would not dedupe across calls (fact 22); durable `commit`/document state is the only conversation-scoped option and nothing in `src/mail/` uses it. Note also `replay: "safe"` (fact 23): after a restart a cached answer may be absent or differ, and nothing may depend on it for correctness.
- **Model/schema identity is not available in the mail tools today.** `MailDeps` carries only `source` and `now` (fact 21); the configured model lives in `Config.model` (`src/config.ts:59`) and per-call on `api.models` (`dist/harness/types.d.ts:163`–`164`), so the cache key's `model` component needs a new injected value.
- **Cannot verify classify's CLI here.** No `screwtape` on PATH in this checkout, and the only end-to-end harness assumes a Home-Manager wrapper with a baked-in `--config` (`test/mail/smoke.test.ts:28`–`45`); the flag names (`--model`, `--schema`) and the exact output field set are unverified assumptions.
