**Inferences (flagged as such)**

- The blank-line separation requirement ("consistently in both live output and the reattached transcript") most plausibly requires either a renderer change (`src/render.ts`, outside declared scope) or an Emacs-side post-processing layer (inside scope). The slice text does not choose; this is the first thing design must settle.
- Because the daemon's transcript replay arrives as a `snapshot` event rendered by the same renderer, live and reattached presentation are structurally the same code path — so an Emacs-only presentation fix is feasible without protocol change, but may diverge from terminal output.
- "Follow output only when the reader is at the end" has no counterpart in `src/attach.ts` or `src/render.ts`; it is purely a comint concern in `emacs/malebolge.el`, which currently has no scroll or marker handling at all (`emacs/malebolge.el:44-52`).
