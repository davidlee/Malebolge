### Assumption checks
- **A1: fork's init can write a session-scoped doc in the same commit — holds, with two constraints.** `ConversationInit` runs in the creating commit and explicitly leaves document access available while table reads throw `ReadAfterWrite` (`dist/harness/types.d.ts:412-416`), and `tx.doc(SessionDocToken)` is a documented transaction operation (`dist/types.d.ts:756`); `fork` accepts `init` (`:622`, `README.md:532`). Constraints: (i) init **cannot** read the parent's `ConversationRecord` — the parent id must come from the call-site closure and the parent's topic from the index document itself; (ii) `conversationCreated` (the alternative seam) also fires for forks but knows no topic, so "one seam" in objective 1 likely means `init`.
- **A2: `scanConversations` cheap at startup — holds for the read itself, fails for a full backfill in one call.** It is a single indexed-prefix scan returning id-ordered record rows with `LIMIT n+1`, no transcript or document hydration (`dist/storage/sqlite/storage.js:138-156`, `dist/types.d.ts:264-275`). But startup backfill must visit *every* conversation, and the API is paged (`dist/types.d.ts:716`); the cursor-loop precedent is `src/runner/durable-ids.ts:27-32`.

### Naming precedents
- Message types are lower-case nouns with a parallel reply noun (`attach`/`attached`, `list`/`conversations`) — `src/protocol.ts:39-57,70-78`.
- Frame refusals are `"<frame>: <problem>"` via `frameRefused`/`attachRefused` (`src/protocol.ts:66-79,90-92`); unknown keys are refused as `unknown key X` (`:87-88`).
